## 新增 P0：通用 TaskPlanner 最小执行集成

承接 Day 4 的计划状态管理与生成入口，将其接入 Agent 主流程：

1. 执行前生成并校验计划，步骤 ID 保持稳定。
2. CLI 装配规划能力与 Runner，每轮请求只携带最新计划，计划参与上下文预算。
3. 提供参数校验后的显式计划更新入口，支持推进、重新打开和替换步骤。
4. 根据工具结果更新进度，记录更新依据，保留完整执行历史；区分模型自述与工具证据。
5. 提供“生成计划 → 工具执行 → 显式更新 → 继续或结束”的可运行示例。

Core 保持通用运行与计划接口，不依赖 CLI、Adapters 或模型 SDK；具体接入形式在 Day 6 开始时结合代码确定，不提前指定新增框架或工作流引擎。

## 验收

- Fake Provider 验证生成、执行、状态更新与下一轮携带最新计划。
- 拒绝未知 ID、非法状态更新和重复 ID；工具失败或取消不误标完成。
- 新计划超出预算时，在下一次模型调用前停止。
- 模型返回普通文本而计划仍未完成时，明确报告未完成；Runtime complete 和退出码 0 不作为任务成功证据。
- 独立执行真实模型验证，记录参数、耗时、计划、工具结果及未完成事项。

暂估6–9h，包含讲解、学习者动手、测试和真实验证；每日总投入不超过10h。以下小时是新估算，不是已发生工时，也不重算原12h+20h为全新工作量。每段记录实际耗时，超出估算先报告余量冲突。

## 1. 调用链与历史事务复盘（1h）

阅读入口：

- `apps/cli/src/commands/session.ts`：装配Provider、工具、预算与Runner。
- `apps/cli/src/session/agent-session.ts`：每轮信号、状态、历史提交与回滚。
- `apps/cli/src/session/console-session.ts`：输入、增量显示、取消与退出。
- `packages/core/src/agent/runner.ts`：模型步骤、工具执行和完整历史。

- [ ] 学习者画出 Session → run → 多次模型请求/工具执行的关系，说明步数在哪一层重置。
- [ ] 推演“第一轮成功，第二轮工具执行后Provider失败，第三轮继续”：逐条列出保留与丢弃的消息，解释历史回滚为什么不撤销工具副作用。
- [ ] 推演运行中与空闲Ctrl+C，说明为什么每轮必须有新AbortController，取消后何时才能接受新任务。

通过标准：无需照读代码，能解释complete、max_steps、任务成功的区别，并准确指出历史提交位置。

## 2. 流式协议与显示边界（1–1.5h）

沿Core ModelEvent/AgentEvent公开定义、Adapters Ollama Provider及流解析器，追踪TEXT_DELTA、DONE.result到Runner的过程；结合 `packages/core/src/agent/runner-streaming.test.ts` 阅读现有协议失败测试。

- [ ] 学习者解释“文本可显示”和“工具参数可执行”为什么是两个不同边界。
- [ ] 推演DONE缺失、DONE后继续输出、流中途失败、多工具响应，说明哪些情况不能保存成功历史。
- [ ] 对比session默认流式和--no-stream路径，明确文本增量只用于显示，最终assistant只保存一次。

通过标准：能解释原生完整工具对象与参数字符串碎片的区别，不把网络分片直接当成工具调用，也不把MODEL_FINISHED当作任务终态。

## 3. 动手补齐组合测试（2–3h）

修改以现有测试文件为主；只有失败测试证明实现缺陷时才改产品代码。学习者至少独立完成一个测试，辅导者补常规覆盖。每项先写断言并确认当前缺口，再运行定向测试；使用可控门闩或事件等待，避免固定sleep判断时序。

- [ ] `tests/integration/session-cli.test.ts`：模拟HTTP先输出一段文字，再阻塞响应结束；子进程必须已显示首段，释放后才允许完成。失败时也必须释放资源。
- [ ] `apps/cli/src/session/agent-session.test.ts`：流式工具已启动时取消，工具收到信号；禁止下一次模型请求，历史回滚；新一轮使用新信号且能完成。
- [ ] 同文件：连续多轮达到必要上下文预算上限，超限请求不调用Provider且不提交用户输入；reset保留系统配置并允许新任务。
- [ ] 同文件或 `packages/core/src/agent/runner-streaming.test.ts`：流式maxSteps保留完整工具配对，下一轮重新计步；相同Fake Provider场景下流式与非流式最终结果、调用顺序及历史一致。

通过标准：测试能区分提前显示与响应结束后回放；取消覆盖工具阶段；预算覆盖累计历史而非只测一次超限。仅确认现有单元测试存在不能替代以上组合行为。

## 4. 真实仓库三轮验收（1–2h）

- [ ] 先确认Ollama可用和模型能力，记录实际服务版本、模型ID/digest、上下文长度、thinking、超时及实际temperature/seed配置；未配置项如实标注。
- [ ] 同一session连续三轮：定位CLI命令注册；追问刚才定位文件中的session装配；进一步解释相关取消与历史边界。每轮要求工具证据，不把正确回答当作工具确实执行的证明。
- [ ] 记录原始工具调用及结果、首段延迟与总耗时。若现有诊断不能提供完整数据，明确证据缺口；复用#26后续追踪补验，不因此提前实现第二套追踪框架。
- [ ] 额外观察取消后继续，以及--no-stream对照。将模型漏目录、忽略截断或无法定位文件等失败与Runtime错误分别记录。

运行产物放入忽略的 `.agent/`；提交文档只保留必要、去敏的摘要。服务缺失时明确未执行，不自动安装或下载模型。

通过标准：三轮历史延续、实际工具证据与耗时可核验；模型失败如实保留，缺证据的项继续待验收。

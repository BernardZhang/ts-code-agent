## 实现与设计

- AgentRunner 位于 Core，通过构造参数注入 ModelProvider 和 ToolExecutor；CLI 负责 Ollama 装配、工具、任务提示及输出。
- 从 Day 2 固定两次请求，演进为“请求模型、保存 assistant、执行全部工具、回传结果、继续请求”的循环。
- assistant 每轮只保存一次，包含文本和完整 toolCalls；每个工具结果保存完整 JSON ToolResult，最终文本也保留在消息历史。
- run 复制输入 messages 数组，避免追加污染调用方；当前不修改既有消息对象，不提供深拷贝隔离。
- maxSteps 要求正的安全整数，仅计算 generate 调用次数。初始用户 prompt 已包含在第一次模型请求中，不单独计步；工具执行不计步。
- 采用学习者选择的 A 策略：最后一次模型响应中的全部工具照常执行，之后返回 max_steps，不追加总结请求。若最后一次响应已无工具调用，则返回 complete。
- 普通工具失败回传给模型，模型可修正参数；任务取消停止后续工作，不撤销已有副作用。Provider 错误原样向上抛出，不自动重试。
- CLI agent-demo 当前固定 maxSteps 为 10。最终回答写入 stdout，模型请求数、工具调用请求数和上限提示写入 stderr。工具请求数包含参数非法的调用，不等于成功执行次数。

## 学习者实践与理解

学习者亲手实现 Runner、测试和 CLI，并完成以下推演及修正：

- 两轮加法的消息历史是 user、assistant、tool、assistant、tool，最终回答再追加 assistant。
- 无工具调用用 return 正常完成，避免 break 后误报达到上限；空数组也表示无调用。
- 修正重复 assistant 消息、遗漏最终回答及信号传递。
- 理解 mockResolvedValueOnce 返回成功响应，mockRejectedValueOnce 模拟拒绝；取消断言应写 await expect(promise).rejects，不能先 await promise。
- 理解 ESM 相对导入需要 .js，类型使用 type 导入；Vitest 通过不等于类型检查通过。
- 工具消息从返回历史按 role 筛选；索引可能不存在，使用显式检查收窄。
- 理解同轮第一个工具中取消后，第二个不应开始，已有副作用不会回滚。
- 继续对话需显式传入完整历史；Runner 实例不保存历史，新一次 run 从头计步。

## 真实模型实验（学习者反馈）

以下来自学习者本次聊天输出与反馈，辅导者未独立重跑真实模型请求：

1. 未赋值变量可能被模型替换成 0，再作为合法数字传给 add；Schema 只能校验类型，不能验证参数有无用户依据。
2. 模型也可能完全不调用工具，擅自假设 b = 5、c = 10，生成答案 65。提供工具不保证模型使用工具，complete 也不保证任务成功。
3. 加入系统规则，要求数值加法调用工具、不得猜测变量。输入“计算1 + 2 + 3 + 4 + 5 + c”时，学习者提供的输出为模型请求 2 次、工具调用 1 次，算出 3 后提前询问 c，未完成已知部分化简。
4. 随后加强“先化简已知数值部分”的提示；没有完整重复实验数据，不能据此声明稳定遵循。
5. 临时追加用户消息“c = 6”，将第一次历史传入第二次 run，学习者反馈得到 21。当前代码已移除固定追问实验，尚无交互式输入。

本次反馈未附实际模型 ID、Ollama 版本、完整参数及耗时。默认配置模型不能作为本次实测模型身份；不引用 Day 1 历史环境补齐本次证据，不给出成功率或性能结论。

## 限制与后续

- 仅支持非流式工具循环；不含交互式多轮输入、持久化恢复、上下文管理、自动重试和任务结果验证。
- 系统提示只能引导；模型可能忽略工具、猜值或提前结束，Runtime 正确性与模型任务效果需分开验证。
- 当前 Agent Demo 没有新增专属 CLI 模拟 HTTP 集成测试；已有 CLI 测试通过不代表新命令所有分支均获覆盖。
- 当前取消检查在入口、模型返回后及每个工具结果保存后；调用前取消和工具内取消已测，尚未覆盖所有异步取消时序。
- 超时与取消不强停忽略信号的工具，也不回滚副作用。
- 本次记录不代表已提交、推送或完成 GitHub Issue；这些操作按学习者授权执行。

## 2026-10-19 Issue #3 验收补充

创建 PR #38 后已成功读取 Issue #3，确认先前“两轮工具 + 最终回答”不能替代“三步连续工具调用”。新增 runner-scheduling.test.ts：

- 三轮连续工具调用，第四次模型请求收到全部三个工具结果，返回最终回答；断言 steps 为 4。
- 显式 toolExecution: EToolExecution.PARALLEL 同时启动同轮独立工具；测试让第一个等待第二个，再让第二个失败，验证全部结果按原调用顺序回传，普通失败不阻塞结果反馈。
- 并行工具全部启动后取消，验证各工具信号都取消，Runner 拒绝且不再请求模型。

默认仍顺序执行，CLI 沿用默认；并行仅适用于相互独立的工具。当前无并发上限，不承诺强制停止或回滚副作用。取消前的已启动工具可能继续产生副作用。本次补充未重跑真实模型；离线验证不代表模型会稳定生成三轮或并行调用。

## 1. 产品与学习目标

构建本地运行的 TypeScript Code Agent CLI：接收开发任务，分析仓库，调用工具，提出或执行代码修改，运行验证，并提供可追踪的执行结果。

采用 6 周、36 个学习日的渐进交付方式。前期使用本机 Ollama；模型接入可替换。用户机器为 Apple M2 Pro、32GB 统一内存。

原 Project 排期从 2026-10-14 开始。用户计划在文档确认后开始学习；实际开工日期及是否调整 GitHub 排期另行确认，本文档不自动修改已有日期。

## 3. Day 1：本地模型接入

### 前置条件

- 用户确认本文、AGENTS.md 与架构文档。
- 在目标仓库的本地 checkout 中工作；确认分支与现有修改。
- 机器默认 Node.js、全局 pnpm 可用；Ollama 服务可访问，`qwen3:8b` 已下载。
- Ollama 为用户单独安装的本地服务；工程初始化不隐含系统安装或模型下载。
- 起步参数：8K 上下文、关闭 thinking、一次一个推理请求。它们是可配置的开发基线，并非永久产品限制。

### P0 功能

1. CLI 接收一条文本提示，调用配置指定的 Ollama 模型，逐步输出文本。
2. 模型地址、名称、上下文长度、超时、thinking 设置集中配置与校验。
3. 支持非流式调用，返回统一结果，保留 Provider 能提供的使用量信息。
4. 支持 JSON Schema 结构化输出；对响应文本进行 JSON 解析和 Zod 校验。
5. Ctrl+C 可中止当前请求并清理资源，CLI 正常结束，无未处理异常。
6. 连接失败、HTTP 错误、超时、格式错误、JSON 解析失败与 Schema 校验失败有可区分反馈。
7. 仅初始化 Day 1 使用的 CLI、Core 和 Adapters 包；不生成后续阶段的占位实现。

### P1 功能

- 显示首次输出延迟、总耗时和模型提供的 token 统计。
- 提供交互式多轮聊天；Day 1 的单次命令验收不依赖此功能。

### 建议命令行为

`chat`：传入提示，默认流式输出；`--no-stream` 使用非流式结果。

`structured-demo`：运行一个固定的任务规划 JSON Schema 示例，输出通过 Zod 校验的数据。此命令用于学习，不等同于已实现 TaskPlanner。

具体参数名在实现时统一记录到 README；配置优先级为命令参数 > 环境变量 > 默认值。

### Day 1 验收标准

| 场景           | 验收结果                                                       |
| -------------- | -------------------------------------------------------------- |
| 正常文本请求   | CLI 输出模型文本，退出码 0                                     |
| 流式请求       | 未等完整响应即开始输出；结束信号正确处理                       |
| 分片边界       | 模拟 HTTP 字节分片跨 UTF-8 字符、JSON 行与多行时，解析不丢内容 |
| 结构化响应     | JSON 可解析且通过 Zod；不合法响应明确失败                      |
| 用户取消       | 请求中断，无未处理异常，取消退出码约定为 130                   |
| 网络或协议失败 | 错误写入 stderr，非零退出码，不误报成功                        |
| 工程检查       | 类型、测试、lint、格式与构建命令通过                           |
| 真实模型验证   | 记录模型 ID、Ollama 版本、关键参数和结果；未执行时明确标注     |

Day 1 不实现工具调用、Agent Loop、Checkpoint、RAG 或补丁引擎。

## 4. 后续核心需求

- 工具调用：参数校验、明确结果、超时与取消、失败反馈；工具参数完整后才执行。
- Runtime：最大步骤和预算控制、显式状态、完整工具结果回传、可靠终止。
- Context：保留完整的工具调用/结果关系，控制工具输出和历史长度。
- 恢复：快照版本化，可序列化；恢复后重新装配工具与连接，避免重复副作用。
- 代码操作：路径限定在工作区，读写和命令分别授权，输出长度受控。
- 验证：以任务结果为依据，区分运行成功、测试成功和用户需求完成。
- 评测：固定小型仓库和任务，记录成功率、耗时、步骤与资源信息，不将模型表现等同于 Runtime 正确性。

## 5. 质量要求

默认测试离线、可重复。真实模型测试单独触发。系统配置不依赖个人绝对路径；运行日志、凭据与完整私有代码不默认提交或记录。

Day 1 不承诺固定生成速度；速度和内存压力在本机实测。后续接口和界面通过统一事件及运行状态复用核心，当前不实现网络服务。

## 6. Day 2：工具定义、注册与执行

- Core 定义 ToolDescription、ToolDefinition、RegisteredTool 和 ToolResult；注册表拒绝重名并提供不含执行函数的描述列表。
- 执行前校验参数；未知工具、非法参数、执行失败、超时、取消分别返回明确错误码。
- 超时默认 10 秒，支持调用选项覆盖，校验有限正整数及 Node 定时器上界；结束后清理定时器和取消监听器。
- Ollama 非流式协议映射包含工具描述、调用及结果消息；工具参数完整后才执行。
- CLI tools-demo 演示固定两次模型请求及中间一轮工具执行；不实现 Day 3 自动循环。
- 流式工具调用当前明确拒绝，不静默丢弃。超时取消不能保证停止忽略信号的工具，也不回滚副作用。
- 实际工程检查、真实模型演示的证据来源及剩余验证见 docs/learning/day-02.md。

## 7. Day 3：Agent Loop

- Core AgentRunner 注入 ModelProvider 与 ToolExecutor，支持非流式模型请求，默认顺序执行工具，可显式选择并行；不依赖 Ollama 或 CLI。
- 每轮保存完整 assistant 消息和全部 tool 结果；最终回答也保留在历史中。复制输入消息数组，运行中仅追加，不修改调用方数组。
- maxSteps 为正的安全整数，统计模型请求次数；用户初始消息和工具执行不额外计步。
- 无工具调用时返回 complete；额度耗尽且仍有工具调用时，执行完最后一轮工具后返回 max_steps，保留消息历史，不额外请求总结。
- 普通工具失败回传模型；用户取消抛出取消异常；Provider 错误向上抛出，不自动重试。
- agent-demo 装配计算工具，当前上限固定为 10；回答输出到 stdout，统计和上限提示输出到 stderr。
- 离线验收覆盖直接回答、至少三轮连续工具、并行启动与有序结果回传、并行取消、上限、参数失败后修正、Provider 失败和非法步数配置。真实模型表现与 Runtime 正确性分开记录。
- complete 不等于任务成功；不包含交互式多轮输入、持久化恢复、上下文裁剪或任务结果验证器。已读取 GitHub Issue #3，补充其三轮连续工具调用与并行工具验收。

并行执行通过 run 的 toolExecution: EToolExecution.PARALLEL 显式启用，仅用于同轮相互独立的工具；依赖其他工具结果的调用应留在下一轮。全部工具结果就绪后才请求模型，消息按原调用顺序保存，普通失败不丢弃其他结果。取消通知已启动工具并停止后续模型请求，不保证撤销或强停副作用。当前不提供并发数量上限；CLI 仍采用默认顺序模式。

## 8. Day 4：上下文预算与任务计划

Core 已实现 ContextManager、整轮历史裁剪、上下文错误分类和 TaskPlanner；CLI 提供 plan-demo、context-demo，并在 agent-demo 中装配预算。Runner 每轮构建请求上下文并保留完整历史。必要消息放不下时在请求前失败，不静默截断。

预算扣除输出预留与工具定义成本，保留全部 system 和当前用户轮次，再选择连续的最近历史轮次。计划支持稳定 ID、状态更新和步骤替换。模型计划通过 CLI 的 Zod 边界校验，Core 不依赖 Zod。

实际验证与剩余验收见 docs/learning/day-04.md。启发式估算不是精确 token 数；单个长轮次未压缩，超限时停止，不能宣称长任务可无限继续。计划生成和 Runtime complete 不等于用户任务成功。

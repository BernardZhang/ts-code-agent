# ts-code-agent 需求规格

状态：待用户审阅。本文档不代表工程已初始化或功能已实现。

## 1. 产品与学习目标

构建本地运行的 TypeScript Code Agent CLI：接收开发任务，分析仓库，调用工具，提出或执行代码修改，运行验证，并提供可追踪的执行结果。

采用 6 周、36 个学习日的渐进交付方式。前期使用本机 Ollama；模型接入可替换。用户机器为 Apple M2 Pro、32GB 统一内存。

原 Project 排期从 2026-10-14 开始。用户计划在文档确认后开始学习；实际开工日期及是否调整 GitHub 排期另行确认，本文档不自动修改已有日期。

当前不包含 Web、HTTP API、多用户、登录、计费、模型微调或生产部署。后续可增加这些能力，但不提前创建目录和实现。

## 3. Day 1：本地模型接入

### 前置条件

- 用户确认本文、AGENTS.md 与架构文档。
- 在目标仓库的本地 checkout 中工作；确认分支与现有修改。
- Node.js LTS、pnpm 可用；Ollama 服务可访问，`qwen3:8b` 已下载。
- Ollama 为用户单独安装的本地服务；工程初始化不隐含系统安装或模型下载。
- 起步参数：8K 上下文、关闭 thinking、一次一个推理请求。它们是可配置的开发基线，并非永久产品限制。

### P0 功能

1. CLI 接收一条文本提示，调用配置指定的 Ollama 模型，逐步输出文本。
2. 模型地址、名称、上下文长度、超时、thinking 设置集中配置与校验。
3. 支持非流式调用，返回统一结果，保留 Provider 能提供的使用量信息。
4. 支持 JSON Schema 结构化输出；对响应文本进行 JSON 解析和 Zod 校验。
5. Ctrl+C 可中止当前请求并清理资源，CLI 正常结束，无未处理异常。
6. 连接失败、HTTP 错误、超时、格式错误、JSON 解析失败与 Schema 校验失败有可区分反馈。
7. 仅初始化 Day 1 使用的 CLI、Core 和 Adapters 包；不生成后续阶段的占位实现。

### P1 功能

- 显示首次输出延迟、总耗时和模型提供的 token 统计。
- 提供交互式多轮聊天；Day 1 的单次命令验收不依赖此功能。

### 建议命令行为

`chat`：传入提示，默认流式输出；`--no-stream` 使用非流式结果。

`structured-demo`：运行一个固定的任务规划 JSON Schema 示例，输出通过 Zod 校验的数据。此命令用于学习，不等同于已实现 TaskPlanner。

具体参数名在实现时统一记录到 README；配置优先级为命令参数 > 环境变量 > 默认值。

### Day 1 验收标准

| 场景 | 验收结果 |
| --- | --- |
| 正常文本请求 | CLI 输出模型文本，退出码 0 |
| 流式请求 | 未等完整响应即开始输出；结束信号正确处理 |
| 分片边界 | 模拟 HTTP 字节分片跨 UTF-8 字符、JSON 行与多行时，解析不丢内容 |
| 结构化响应 | JSON 可解析且通过 Zod；不合法响应明确失败 |
| 用户取消 | 请求中断，无未处理异常，取消退出码约定为 130 |
| 网络或协议失败 | 错误写入 stderr，非零退出码，不误报成功 |
| 工程检查 | 类型、测试、lint、格式与构建命令通过 |
| 真实模型验证 | 记录模型 ID、Ollama 版本、关键参数和结果；未执行时明确标注 |

Day 1 不实现工具调用、Agent Loop、Checkpoint、RAG 或补丁引擎。

## 4. 后续核心需求

- 工具调用：参数校验、明确结果、超时与取消、失败反馈；工具参数完整后才执行。
- Runtime：最大步骤和预算控制、显式状态、完整工具结果回传、可靠终止。
- Context：保留完整的工具调用/结果关系，控制工具输出和历史长度。
- 恢复：快照版本化，可序列化；恢复后重新装配工具与连接，避免重复副作用。
- 代码操作：路径限定在工作区，读写和命令分别授权，输出长度受控。
- 验证：以任务结果为依据，区分运行成功、测试成功和用户需求完成。
- 评测：固定小型仓库和任务，记录成功率、耗时、步骤与资源信息，不将模型表现等同于 Runtime 正确性。

## 5. 质量要求

默认测试离线、可重复。真实模型测试单独触发。系统配置不依赖个人绝对路径；运行日志、凭据与完整私有代码不默认提交或记录。

Day 1 不承诺固定生成速度；速度和内存压力在本机实测。后续接口和界面通过统一事件及运行状态复用核心，当前不实现网络服务。

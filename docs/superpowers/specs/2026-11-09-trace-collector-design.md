# TraceCollector 与本地文件追踪设计

日期：2026-11-09，已由学习者确认并分步实现；2026-11-12当前实现与验证见[学习验收](../../learning/trace-collector.md)。以下保留设计阶段表述，后续ruling以实现记录为准。关联 Issue #26，承接 #46 生命周期事件。

## 目标和当前基线

目标是可用于本地单进程 CLI 的诊断追踪，提供有界资源、脱敏、批量写入、可检查的完整性和失败轨迹。学习者需解释背压、文件写入确认与持久性差异，亲手完成一个故障测试。

当前 AgentEvent 已包含 run/model/tool 生命周期、runId、step、toolCallId 和 elapsedMs；此前实际验证280项测试通过，这属于历史证据。TraceCollector、文件存储和CLI展示尚待实施。原始 onEvent 是同步回调。

采用诊断模式。正常关闭成功时，关闭屏障前已接受的记录全部完成文件写入。进程崩溃、SIGKILL或断电时，尚未持久化的尾部可能丢失。对已写入文件也不承诺断电持久性。需要持久化确认的模式另列增量，必须设计同步到磁盘的确认边界和恢复机制。

## 数据流与包职责

AgentRunner → 同步CLI事件分发 → Core TraceCollector → 脱敏记录 → Adapters FileTraceWriter。

Core定义记录格式、脱敏、序号、摘要与异常规则，不依赖文件系统。Collector提供同步record(event)，返回可写记录，及getSnapshot(runId)，返回独立摘要快照。每次run独立Collector，CLI结束该run并完成收尾后释放内存。CLI展示原始增量，同时把脱敏记录交给写入器。

Adapters提供FileTraceWriter及逐行读取器。公开接口拟定为enqueue(record): admission、flush(): Promise<report>、close(): Promise<report>。enqueue同步有界入队，admission表明接受或拒绝；flush和close明确返回成功、失败或超时。公共状态、原因和错误码统一用类型及枚举。CLI负责装配、报告追踪完整性、退出等待及文件清理策略。

## 记录、脱敏与关联

JSONL每行一个版本化信封，包含schemaVersion、sequence、runId、事件type与elapsedMs。sequence在接收时递增，丢弃记录同样消耗序号，便于识别缺口。run头部记录UTC开始时间和有限配置元数据，用于将相对耗时关联至时间点。

按事件类型显式构造允许字段。TEXT_DELTA只保留元数据。工具事件保留toolName、toolCallId、step和结果状态/错误码；模型结束可保留token统计；run结束保留状态、步数和错误码。默认省去正文、路径参数、工具输出和异常message/stack。finishReason作为外部字段需按允许值归一化，未知值仅标记未知，避免泄漏。

同一个run中按step关联模型请求，按toolCallId关联工具，同名调用可区分。时间线按接收序号排列，工具历史继续按模型原始调用顺序排列。

## 摘要和异常

摘要实时更新，不在内存保存全部TEXT_DELTA。保存run状态、模型步骤、工具调用及计数。模型和工具摘要有配对开始/结束时才生成durationMs。只有就绪时保存readyAtMs；缺少开始的结束事件保留结果和finishedAtMs，耗时留空并标记缺失。

重复事件和run终态后的事件仍进入磁盘时间线，状态采用首次有效转换，标记异常。Collector在已关闭后拒绝写入并计数。run取消时，仅有ready的工具标记未执行，有started而无finished的工具标记结果缺失。模型已经finished的记录维持完成，不因后续工具失败改变。

元数据也有容量限制：每run最多1024个模型步骤摘要、4096个工具摘要、256条异常样例。超过时只增加计数并标记summaryTruncated，磁盘事件继续按写入策略接收。这些是待压测校准的默认值。Collector入站先校验runId/toolCallId最长128个UTF-8字节、toolName最长256个字节、step/sequence为非负安全整数、elapsedMs为有限非负数。异常只保存枚举原因及序号，不保存任意错误文本。超限输入拒绝进入摘要并累计计数，文件输出同样只使用校验后的字段。

## 批处理与容量策略

文件位于.agent/traces，目录0700、文件0600，runId需安全编码为文件名。独占创建文件，防止覆盖已有轨迹。一个run一个文件，保持句柄打开并串行写入。

初始默认值为64KiB批次、100ms最早等待触发、1MiB待写字节上限、64KiB单条记录上限。入队字节统计必须包含正在写入但尚未完成的批次，避免双缓冲突破上限。批量值为初始设计参数，不是性能测试结果。

当前同步onEvent采用非阻塞、有界、可报告丢弃的策略。满队列时拒绝当前记录，累计总丢弃数和首尾丢弃序号。额外预留8KiB控制空间，单个run的首次终态槽和完整性页脚各最多4KiB。重复终态按普通记录入队并标记异常，控制槽按sequence顺序写入，不能绕过已接受记录。控制空间计入总内存预算和磁盘配额。每个文件页脚包含accepted、written、dropped、oversized、writeFailed计数和最后接收序号。页脚缺失代表未确认正常收尾。

高频文本事件仍逐条生成脱敏记录，批量后写入。不得把onEvent改为async却不等待其Promise。若未来选择阻塞背压，需要显式修改Runner回调契约并验证取消和异常语义。

## 写入、关闭及恢复

写入器处理部分写入，保留未写完的偏移；只允许一个在途写操作，防止顺序交错。flush屏障覆盖调用前已接受的序号，后续记录属于后续批次。

close禁止新入队，排空、写页脚、关闭句柄；多次close返回同一结果。默认5秒是等待结果的报告期限。超时报告未确认写入数量并标记不完整，停止接收新记录，保留一个后台收尾Promise继续等待在途IO并关闭句柄。正常CLI退出可能因此继续等待，不能承诺5秒内强制退出。SIGKILL由操作系统关闭句柄，重启读取按未确认结束处理。严格退出时限需要隔离writer进程，另行估时。flush与close超时报告不得声称底层IO已取消。

ENOSPC、EACCES等错误使writer进入失败态，后续入队明确拒绝；通过独立stderr诊断报告一次，并保留错误码和计数。Agent的任务状态和追踪状态分别展示，追踪失败不会被误当模型成功或失败。

读取器逐行解析unknown并校验版本和字段，限制单行大小。完整前缀可读取，损坏尾行标记truncated。中间损坏行、序号缺口、缺失终态或页脚均报告，禁止伪造已完成run。恢复用于查看轨迹，任务恢复继续由#10负责。

默认文件保留7天、目录配额256MiB，启动及run结束时只清理符合追踪命名规则的已关闭文件，优先最旧文件，保护活动文件。每次批次追加前先检查及预留字节，包含活动文件、在途批次和8KiB控制空间；达到配额则停止接受该run普通事件，增加拒绝计数并用预留空间尝试写终态及页脚。目录只支持单个CLI writer进程独占拥有，重复启动需通过独占目录锁拒绝第二写入者，异常遗留锁需先校验所有者存活情况，不能盲删。配额无法回收时拒绝开启新追踪并明确报告。文件保留期限内受磁盘可用性约束。

## 验收表

| 场景                             | 必须证明的行为                                                   |
| -------------------------------- | ---------------------------------------------------------------- |
| 并行逆序、普通工具失败和maxSteps | ID配对、真实顺序、耗时、唯一run终态及原始历史顺序                |
| Provider断流、取消、预算失败     | 完成与失败事实准确，下一轮可用，追踪不提前提交历史               |
| 缺失/重复/迟到事件               | 时间线留痕，摘要首次有效，异常有计数                             |
| 脱敏、外部对象修改               | 正文测试标记不在文件/快照中，修改输入或快照不污染内部状态        |
| 慢IO和满队列                     | 在途字节计入上限，内存有界，丢弃可见且终态/页脚可处理            |
| 小批次/定时/flush并发            | 写入顺序稳定、无丢重、屏障语义正确、无需固定sleep猜时序          |
| 部分写入及磁盘错误               | 不重复写前缀、失败可报告、拒绝后续入队                           |
| close重复/退出超时               | 幂等、结果可核验、资源收尾，无静默成功                           |
| 杀进程后重读                     | 完整前缀可用，尾损坏和未结束run可识别                            |
| 配额/保留/权限                   | 活动文件受保护，满盘行为明确，文件权限符合设置                   |
| 高事件速率                       | 记录运行环境、吞吐、缓冲高水位、写入次数及延迟，以测量校准默认值 |

所有默认测试离线。真实CLI演示使用既有Ollama，记录实际配置与文件证据。通过工程检查与故障测试后才报告对应验收通过。
